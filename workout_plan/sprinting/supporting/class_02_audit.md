## Review, comparisons and revisions

| Decision | Alternatives considered and audit result |
|---|---|
| Half-kneeling main start | The preceding standing start addressed a higher static stagger. A low kneeling origin changes starting support and hip/knee position and makes standing-up-before-driving observable. A falling start would prioritize accepting a moving body; a prone start would add a substantial hand-release/get-up task. Half-kneeling better matches today's flexed-leg push/recovery job. This is not a block-start or isolated-leg force test. |
| Four starts, not six | Novel origin plus unknown feedback justifies reducing attempts from six to four, retaining paired lead-leg opportunities and full rest. Distance is unchanged; first pair establishes stopping feasibility. Quality feedback comes within these attempts, not extra testing. |
| Wall switch | Its external support constrains whole-body travel and helps isolate reciprocal thigh action in an inclined position. This is materially different from Class 1's upright skipping, whose step-hop rhythm remains absent here. A solid wall is unconfirmed, so the class supplies a floor-supported rapid-exchange replacement with its different support limitation stated. |
| Seated vertical jump | Supported sitting to leg extension differs from Class 1's standing static horizontal jump. An external seat reduces the role of an immediate dip, but does not justify claiming all elastic contributions disappear. No target box or hurdle is added; floor landing avoids a height contest and extra descent impacts. It is a small bilateral support task for force from flexed legs, not the main sprint drill. |
| Split-base jump | Both feet take off and return to the same split relationship. Its asymmetric extension/receiving base differs from Class 1's single-leg horizontal takeoff to bilateral parallel landing. Alternating scissor jumps would introduce a midair leg-switch task that is unnecessary for today's push; the default does not use them. |
| Unilateral pogo | A same-leg repeat is a real support-demand change, not renamed bilateral pogo. Initial consideration of four hops/leg was reduced to **three/leg** because response is unknown and direct calf lifts remain. No numerical contact-equivalence argument is used. Bilateral recurrence is explicitly available if readiness requires it. |
| Low dribble | Alternating running contacts with a low circular recovery are distinct from A-skip step-hop pairs. Stationary execution fits the gym and is logged as an authored adaptation, not bound to the traveling library card. The six-contact bouts prevent drift into endurance work. |
| All eight strengthening tasks retained | Their jobs still directly match the low start, thigh recovery and ankle support, and the explosive tasks already change. Prescribed dose/tempo/implements remain stable so actual load/RIR can become comparable when reported. Retention is not evidence that earlier loads were used, nor an instruction to increase them. |
| Hip/hamstring overlap | P1 and P2 already supply two challenging compound patterns. P3 addresses the opposite action (thigh lift), P4 adds knee-flexor support through changing knee angle. One walkout set prevents turning the posterior-chain support slot into another full hinge workout. |
| Calf overlap | Starts, wall switches, pogo and dribble all load foot/ankle tissues differently. Keep only three calf working bouts, preserve low rebound amplitude and do not add contacts to fill recovered time. Lower event counts alone do not prove lower tissue stress. |
| Recovery and chronology | Main task first; isolated/static leg-force tasks precede the upright contact doses; light strengthening remains easy before loaded work. Rest is kept despite a reduced main-start count. Every row has a stop/regress condition. |
| User preference | Six default drills differ from Class 1 by origin, support, direction or cyclic pattern, not just load/name. Explicit readiness/equipment fallbacks may recur. Record that truth instead of presenting a fallback as unique. Strength recurrence follows the user's stated exception. |
